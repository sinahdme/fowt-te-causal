Jeon, H.\*, Lee, I.-S., Roh, J.-K. (2025). "Reinforcement Learning Based
Floating Offshore Wind Turbine Substructure Design Variable Optimization"
(강화학습 기반 부유식 해상풍력 하부구조물 설계변수 최적화). KSME 2025,
Kangwon Land, 2025-12-12.

This is **predecessor work by the project owner**. The optimisation
problem it defines is what the present TE + Sobol/MI project performs
causal analysis on. Treated as the canonical problem-definition source —
not an external paper to compare against.

## TL;DR

- **Goal**: minimise FOWT substructure mass while keeping geometric,
  dynamic-stability, and resonance constraints satisfied.
- **Platform**: IEA-22MW-RWT-Semi (UMaine semi family, scaled to 22 MW).
- **7 design variables** parameterising the semisub geometry.
- **Optimiser**: DDPG reinforcement-learning agent, with LHS-seeded random
  initialisation (1000 starting points) and mid-training re-exploration.
- **Environment**: WISDEM/RAFT frequency-domain coupled solver inside the
  RL loop — fast surrogate for the time-domain OpenFAST solver.
- **Validation**: 26 optimised candidates → OpenFAST DLC 1.6 (6 seeds each).
  Case_03 selected; **mass reduced 21.5 %** vs baseline.
- **Trade-off finding**: mass reduction concentrates load into platform
  motions and mooring tensions because the mooring is sized for the baseline.
  Authors recommend joint platform + mooring optimisation as next step.

## Constraints

**Geometric** (physical-feasibility hard constraints):
- `D_OCol > D_Pt` — offset column wider than pontoon
- `H_Pt > 0.5 · D_Pt` — pontoon height > pontoon radius (avoid flat shapes)
- `H_Draft > 0.5 · D_Pt + H_Pt` — submergence of pontoon top

**Dynamic stability**:
- `C₅₅ > C₅₅_limit` — pitch restoring coefficient floor
- `|Acc_nacelle| ≤ 2.0 m/s²`
- `max|Pitch| ≤ 6°`
- `Pitch_peak ≤ 3.6579` (RAO peak threshold)
- `Heave_peak ≤ 120.0768`

**Resonance avoidance**:
- Pitch natural frequency must be > ±20 % away from wave peak frequency
- Heave natural frequency must be > ±20 % away from wave peak frequency

Constraint violation in the RL loop → reward `−100` penalty.

## Objective (RL reward)

$$
R_\text{total} = 1.3 \cdot \Delta\text{Mass}
              + 0.3 \cdot \Delta\text{Resonance}
              + 0.5 \cdot \Delta\text{Pitch}_\text{peak}
              + 0.2 \cdot \Delta\text{Heave}_\text{peak}
$$

Weights reflect: Mass (1.3) = top priority (cost); Pitch peak (0.5) =
power-generation impact; Resonance (0.3) = redundant with hard constraint
so demoted; Heave peak (0.2) = lower priority.

## RL setup

- **Algorithm**: DDPG (continuous-action actor-critic).
- **State `s_t`**: 7 design variables + 12 RAFT analysis outputs.
- **Action `a_t`**: incremental change in design variables.
- **Environment**: WISDEM/RAFT frequency-domain coupled aero-hydro-servo-elastic
  surrogate. Chosen because time-domain (OpenFAST) is too slow for
  inner-loop RL.
- **Random initialisation**: 1000 LHS starting points for global exploration.
- **Mid-training re-exploration**: when DDPG converges or reward stalls,
  generate a new exploration vector `0.8 · (optimisation direction) + 0.2 · (random direction)`.

## Response channels logged (9)

These become the **TE targets and Sobol response variables** for this
project (locks Q1 in [[open-questions]]):

- Structural loads: `RootMyc1` (blade-root flapwise moment),
  `RootMxc1` (blade-root edgewise moment), `TwrBsMyt` (tower-base moment).
- Platform motions: `PtfmHeave`, `PtfmSurge`, `PtfmPitch`.
- Mooring: `FAIRTEN1`, `FAIRTEN2`, `FAIRTEN3` (fairlead tensions per line).

## Validation result (Case_03 vs Baseline)

| Quantity | Δ vs baseline |
|---|---|
| Mass | **−21.5 %** ✓ |
| Blade root flapwise moment (max) | −7.5 % |
| Blade root edgewise moment (max) | +2.4 % |
| Tower base moment (max) | −2.0 % |
| Platform surge (max) | **−39.7 %** ✓ |
| Platform heave (max) | **+32.3 %** ⚠ |
| Platform pitch (max) | +10.3 % ⚠ |
| Fairlead tension 1 (max) | +19.1 % ⚠ |
| Fairlead tension 2 (max) | **+58.9 %** ⚠ |
| Fairlead tension 3 (max) | **+57.4 %** ⚠ |

**Authors' conclusion**: the mooring system is sized for the baseline,
so removing platform mass concentrates load into mooring tensions and
heave/pitch motions. Joint platform + mooring optimisation needed.

## How it informs this project

- **Locks Q1 (response channels)**: the 9 channels above are our TE
  targets and Sobol/MI response variables.
- **Locks Q2 (structural parameters)**: the 7 design variables above are
  our Sobol/MI sweep parameters (ranges still owed by user).
- **Partially locks Q3 (summary statistics)**: `max` per channel is the
  predecessor's choice. We will *also* compute `std`, DEL, and mean —
  TE/MI on std and DEL is more meaningful for fatigue-relevant drivers,
  and is the gap our work fills.
- **Strong candidate for Q9 (design-decision case study)**: the trade-off
  table above is exactly the kind of "Sobol-only analysis cannot resolve
  this" narrative the publication strategy needs. **Conditional TE on
  (wind, wave) → fairlead-tension std**, combined with Sobol-`ST` on
  (geometry, mooring length) → fairlead-tension std, can disentangle:
  *is the mooring-tension penalty wind-driven (controller-mediated) or
  wave-driven (surge-coupled)?* Sobol on the geometry alone cannot tell
  you, because mooring is held fixed in this study.
- **Reference-platform decision**: project keeps IEA-15MW VolturnUS-S as
  the primary platform (more validation literature), and adopts
  IEA-22MW-RWT-Semi as the **second platform for the Q5 multi-platform
  comparison** — giving direct continuity with this predecessor work.
  See [[entities/iea-22-280-rwt-semi]] *(stub)*.
- **RAFT as an intermediate**: the WISDEM/RAFT frequency-domain solver
  used in the RL loop is potentially a faster Sobol/MI ensemble target
  before committing to the full OpenFAST campaign. Worth a decision point
  in Phase 2 (TBD whether to keep RAFT in our pipeline or go OpenFAST-only).

## Open questions / contradictions

- **Ranges for the 7 design variables are not printed.** The optimiser's
  LHS used some box bounds — we need those from the user (or to define
  our own, e.g. ±20 % per variable around baseline).
- **Damping coefficient `C₅₅` limit value** not given numerically; reads
  as "minimum threshold computed per design" but the formula isn't
  specified in the slides.
- **The IEA-22 baseline geometry differs from IEA-15 VolturnUS-S.** When
  we run Sobol on the IEA-15 primary platform, the 7 design variables
  need their baselines re-mapped to VolturnUS-S geometry. Not a
  contradiction — just a mapping task before Phase 2.
